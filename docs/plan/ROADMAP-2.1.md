# План 2.1 — .NET 10, Server 2016, обмен задачами и живой статус

Статус: релиз 2.1.0 опубликован 2026-11-06. Финальный комплект собран
в `./published`, MSI 2.1.0 — 49,8 МБ; тег и GitHub Release созданы.
Остался smoke на реальной ВМ Server 2016 (Desktop Experience и Core).
Доска задач: `./docs/plan/TASKS.md`, раздел «Phase 3».
Связанные документы: `./docs/contracts/IPC.md`, `./docs/contracts/UI.md`,
`./docs/contracts/INSTALL.md`, `./docs/contracts/SECURITY.md`.

## 1. Цели релиза 2.1

1. Перевести UI, общие модели и тесты на **.NET 10 LTS**.
2. Снизить минимальную ОС до **Windows 10 1607 / Server 2016 (build 14393)**,
   сохранив поддержку 1809+/Server 2019+.
3. Добавить **экспорт и импорт задач**: одна задача или несколько выбранных,
   файл JSON, без секретов.
4. Добавить **автообновление статуса** задачи после ручного запуска: список
   должен сам показывать завершение или ошибку, без F5.
5. Не менять модель прав и не расширять поверхность атаки службы.

## 2. Предлагаемые решения

## 3. .NET 10 (Track H)

### 3.1. Контекст

- Текущий TFM: `net8.0-windows` (UI), `net8.0` (Shared/тесты).
- .NET 8 — LTS, но поддержка заканчивается **10.11.2026**.
- .NET 10 — LTS до **14.11.2028**; Windows Server 2016 входит в список
  поддерживаемых ОС (включая Desktop Runtime).
- Runtime по-прежнему поставляется **self-contained**: на сервере .NET ставить
  не нужно.

### 3.2. Ограничение инструментов

Официально targeting `net10.0` поддерживается **Visual Studio 2026 (18.0+)**
или `dotnet build` из SDK 10.0.4xx. На машине сборки стоит VS 2022 17.14.31
и SDK 10.0.403: MSBuild из VS 2022 может выдать `NETSDK1209`/`NETSDK1233`.

Мероприятия:

- перевести сборку управляемых проектов на `dotnet build` (SDK 10.0.4xx);
- C++ проекты (`WinShedulerSvc.vcxproj`, `WinShedulerCA.vcxproj`) оставить на
  MSBuild из VS 2022;
- `./scripts/build.ps1` разделить на два шага: `dotnet build` для C#,
  MSBuild — только для нативных проектов;
- при желании собирать всё через VS — установить VS 2026, но это не обязательно
  для CLI-сборки;
- зафиксировать SDK в `./global.json` (`version: 10.0.403`,
  `rollForward: latestFeature`).

## 5. Экспорт и импорт задач (Track X)

### 5.1. UX

- `DataGrid` переводится в режим множественного выбора
  (`SelectionMode=Extended`, `SelectionUnit=FullRow`).
- Контекстное меню и панель действий:
  - «Экспорт задачи…» — выбрана одна;
  - «Экспорт выбранных (N)…» — выбрано несколько;
  - при пустом выборе команда недоступна;
  - «Импорт задач…» — доступна всегда.
- Экспорт: `SaveFileDialog`, фильтр `*.wstasks.json`, имя по умолчанию
  `winsheduler-tasks-YYYYMMDD-HHmm.wstasks.json`.
- Импорт: `OpenFileDialog`, предпросмотр (список задач, предупреждения),
  выбор режима, прогресс, отмена, итоговый отчёт.
- Экспорт «все видимые» в 2.1 не делаем — только выбранные.

### 5.2. Формат файла

```json
{
  "format": "winsheduler.tasks",
  "formatVersion": 1,
  "exportedAt": "2026-11-06T12:00:00Z",
  "appVersion": "2.1.0",
  "tasks": [
    {
      "id": "8f1c2c1e-4a0b-4c1e-9a6e-1f2d3c4b5a60",
      "name": "Ночной бэкап",
      "description": "Копирование на NAS",
      "enabled": true,
      "programPath": "d:/scripts/backup.cmd",
      "arguments": "--full",
      "workingDirectory": "d:/scripts",
      "windowStyle": "Hidden",
      "sessionMode": "Headless",
      "runAsUser": null,
      "runAsDomain": null,
      "hasPassword": false,
      "onError": "Retry",
      "retryCount": 2,
      "onOverlap": "WaitComplete",
      "timeoutMinutes": 60,
      "killOnTimeout": true,
      "logOutput": true,
      "maxHistoryRecords": 1000,
      "timeWindows": [
        {
          "id": "…",
          "type": "ExactTimes",
          "kind": "Daily",
          "exactTimes": ["02:00"],
          "dayInterval": 1
        }
      ]
    }
  ]
}
```

Правила:

- `format` и `formatVersion` обязательны; версия больше 1 — отказ
  «Файл создан более новой версией WinSheduler».
- Неизвестные поля игнорируются (прямая совместимость).
- `owner`, `createdAt`, `modifiedAt`, `password`, `encryptedPassword`,
  `runAsPasswordEncrypted` в файл не попадают.
- `hasPassword` — только информационный флаг для предупреждения при импорте.
- `id` — идентификатор источника; используется для поиска конфликтов,
  но не является привилегией (служба всё равно проверяет права).

### 5.3. Экспорт

1. Пользователь выбирает одну или несколько задач.
2. UI для каждой задачи вызывает `GetTask` (он возвращает `timeWindows`).
3. Собирается документ, удаляются секретные поля.
4. `SaveFileDialog` → запись UTF-8 без BOM.
5. Ошибка любой задачи — экспорт прерывается, файл не создаётся.
6. В файл не попадают задачи, недоступные пользователю (служба откажет
   в `GetTask`).

Почему на стороне UI: кадр IPC ограничен 1 МиБ, а пакетный экспорт 1000 задач
может его превысить. UI уже имеет доступ к данным; новых действий в контракте
IPC не появляется.

### 5.4. Импорт

1. Чтение файла (лимит 8 МиБ), разбор JSON, проверка `format`/`formatVersion`.
2. Локальная валидация: имена, пути, `HH:mm`, диапазоны, количество.
3. Предпросмотр: таблица задач, предупреждения:
   - `hasPassword=true` — потребуется повторно задать пароль;
   - `runAsUser` задан, а пользователь не администратор — задача будет
     отклонена службой;
   - совпадение `id` с существующей задачей;
   - путь программы/каталога не существует на этой машине (предупреждение,
     не ошибка).
4. Выбор режима (по умолчанию «копия»):

| Режим | Поведение |
|-------|-----------|
| `copy` | всегда `CreateTask` с новым GUID; имя сохраняется |
| `skip` | если `id` есть среди видимых задач — пропустить; иначе `CreateTask` с исходным `id` |
| `overwrite` | если `id` совпал со **своей** задачей — `UpdateTask`; иначе `CreateTask` с новым GUID |

5. Выполнение последовательно, с прогрессом и отменой. Каждая задача — отдельный
   вызов IPC; частичный успех допустим.
6. Перед `CreateTask`/`UpdateTask` идентификаторы триггеров
   (`timeWindows[].id`) очищаются: служба сгенерирует новые. Иначе повторный
   импорт копии даст конфликт первичного ключа в `time_windows`.
7. Отчёт: `imported`, `skipped`, `updated`, `failed` + причина по каждой
   ошибке; кнопка «Копировать отчёт».
8. После импорта — обновление дашборда.

Ограничения: не более 5000 задач в файле, не более 1000 триггеров на задачу,
строки — в пределах лимитов IPC (64 КиБ).

### 5.5. Секреты и права

- Пароли не экспортируются и не импортируются из файла.
- Если у задачи есть `runAsUser` и `hasPassword=true`, а пароль не задан:
  задача создаётся **выключенной**, в отчёте — предупреждение
  «Задайте пароль и включите задачу».
- Если в файле встретилось поле `password` (ручная правка) — оно игнорируется,
  в отчёт добавляется предупреждение.
- Не-админ импортирует задачи **только себе**; `runAsUser`/`ActiveUser`
  отклоняются службой (существующая политика).
- Админ импортирует задачи себе; сохранение исходного владельца в 2.1 не
  поддерживается (для этого нужно новое действие IPC).
- Перезапись чужих задач невозможна: `UpdateTask` проверяет владельца.

### 5.6. Аудит и логи

- Экспорт — чтение; отдельная запись аудита не создаётся, UI пишет строку
  в локальный лог.
- Импорт — существующие записи `CreateTask`/`UpdateTask` в аудите службы
  (по одной на задачу). Пароли и содержимое файла не логируются.
- Итоговый отчёт импорта пишется в локальный лог UI без секретов.

### 5.7. Тесты

- Round-trip: экспорт → импорт в чистую БД → совпадение полей и триггеров.
- В файле нет `password`, `encryptedPassword`, `runAsPasswordEncrypted`.
- `formatVersion` 2 → понятная ошибка; битый JSON; пустой `tasks`.
- Режимы `copy`/`skip`/`overwrite`; конфликт `id`; чужая задача.
- Не-админ: `runAsUser` отклонён; `ActiveUser` отклонён.
- `hasPassword=true` без пароля → задача выключена + предупреждение.
- Повторный импорт копии: ID триггеров очищаются, конфликта PK нет.
- Лимиты: размер файла, число задач, длина строк.
- UI: доступность команд при 0/1/N выбранных, предпросмотр, отчёт, отмена.

## 6. Живой статус выполнения (Track Y)

### 6.1. Проблема

Сейчас `RunNowBtn_Click` делает один `RefreshAsync` сразу после `RunNow`.
Пока задача выполняется, в колонке «Статус» горит «Выполняется», но после
завершения или ошибки строка не обновляется — нужен ручной F5.

### 6.2. Решение

- После `RunNow` и после любого обновления дашборда UI запоминает задачи
  с `running=true` и запускает цикл сопровождения.
- Цикл опрашивает `GetHistory(taskId, 1)` для каждой сопровождаемой задачи:
  первый элемент истории — текущий/последний запуск (`Running`, `Completed`,
  `Failed`, `Killed`, `Timeout`, `Aborted`).
- Интервал: 2 с первые 30 с, затем 5 с. Ограничение — 24 ч.
- Защита от гонки старта: не останавливаться на первом `Running=false`,
  пока не прошло 5 с или пока задача ни разу не была замечена запущенной.
- Остановка: статус не `Running` два опроса подряд после grace-периода;
  задача удалена; окно закрыто; 24 ч; служба недоступна.
- Обновление строки — точечное, без `IsLoading` и без мигания кнопок.
- Несколько одновременных запусков поддерживаются (множество ID, один цикл).

### 6.3. Отображение результата

- Колонка «Статус»:
  - `Running` → «Выполняется» (акцентный цвет);
  - последний запуск `Failed/Killed/Timeout/Aborted` → «Ошибка»/«Прервано»
    (красный);
  - иначе — «Включена»/«Отключена».
- Колонка «Последний запуск»: дата/время + статус последнего запуска
  (цветовой индикатор, код выхода в тултипе).
- После завершения — не модальный баннер:
  - успех: «Задача “X” завершена»;
  - ошибка: «Задача “X” завершилась с ошибкой (код N)».
  Баннер автоскрывается через 10 с; ошибка не блокирует работу.
- Новые строки — в `Strings.resx`, без литералов в XAML/коде.

### 6.4. Почему не `GetDashboard`

`GetDashboard` собирает расписание и историю по всем задачам (N+1 запросов).
Для опроса раз в 2 с это дорого. `GetHistory(taskId, 1)` — один индексный
запрос на сопровождаемую задачу; новых действий IPC не требуется.

### 6.5. Тесты

- Fake IPC: `Running` → `Completed`; `Running` → `Failed`.
- Гонка старта: первый ответ `Running=false`, затем `Running`, затем
  `Completed` — цикл не останавливается преждевременно.
- Отмена при закрытии окна; остановка при `UNAVAILABLE`.
- Несколько задач: завершение одной не останавливает сопровождение другой.
- UI: статус и баннер меняются без нажатия F5; кнопки не мигают.
