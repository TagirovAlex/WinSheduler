# Контракт обмена задачами v1 (EXCHANGE)

Статус: заморожен. Изменения — только через ADR.
ADR: `./docs/adr/0005-task-exchange.md`.
Связанные документы: `./docs/contracts/IPC.md` (модель `TaskDto`),
`./docs/contracts/DB.md` (хранение задач и триггеров),
`./docs/contracts/SECURITY.md` (секреты и права).

## 1. Назначение и границы

Обмен выполняется силами UI через существующие действия IPC:

- экспорт — `GetTask` для каждой выбранной задачи, затем сборка документа в UI;
- импорт — `CreateTask` / `UpdateTask`, по одному вызову на задачу.

Новых действий IPC, изменений службы и формата БД контракт не требует.
Пакетный экспорт на стороне службы не вводится из-за лимита кадра IPC 1 МиБ.

Владелец импортированной задачи — всегда импортирующий пользователь.
Сохранение исходного владельца в v1 не поддерживается.

## 2. Файл

- Расширение: `*.wstasks.json`.
- Кодировка: UTF-8 без BOM.
- Содержимое: один JSON-объект (документ), без комментариев и trailing comma.
- Имя файла по умолчанию при экспорте:
  `winsheduler-tasks-YYYYMMDD-HHmm.wstasks.json`.
- Максимальный размер файла — 8 МиБ.

Пример документа:

```json
{
  "format": "winsheduler.tasks",
  "formatVersion": 1,
  "exportedAt": "2026-11-06T12:00:00Z",
  "appVersion": "2.1.0",
  "tasks": [
    {
      "id": "8f1c2c1e-4a0b-4c1e-9a6e-1f2d3c4b5a60",
      "name": "Ночной бэкап",
      "description": "Копирование на NAS",
      "enabled": true,
      "programPath": "…/scripts/backup.cmd",
      "arguments": "--full",
      "workingDirectory": "…/scripts",
      "windowStyle": "Hidden",
      "sessionMode": "Headless",
      "hasPassword": false,
      "onError": "Retry",
      "retryCount": 2,
      "onOverlap": "WaitComplete",
      "timeoutMinutes": 60,
      "killOnTimeout": true,
      "logOutput": true,
      "maxHistoryRecords": 1000,
      "timeWindows": [
        {
          "id": "1d7a7f0e-3a52-4d4f-9d4e-2b5f0a6c1e11",
          "type": "ExactTimes",
          "kind": "Daily",
          "exactTimes": ["02:00"],
          "dayInterval": 1
        }
      ]
    }
  ]
}
```

Правила шапки:

- `format` и `formatVersion` обязательны.
- `format` должен быть равен `winsheduler.tasks`; иное значение — отказ.
- Поддерживается только `formatVersion = 1`.
- `formatVersion > 1` — отказ с сообщением
  «Файл создан более новой версией WinSheduler».
- `formatVersion < 1`, отсутствие поля или неверный `format` — отказ
  как повреждённый файл.
- `exportedAt` — UTC ISO 8601 с суффиксом `Z`; информационное поле.
- `appVersion` — версия приложения-экспортёра; информационное поле.
- `tasks` — массив задач. Пустой массив допустим: импорт ничего не делает,
  отчёт содержит нулевые счётчики.

Неизвестные поля на любом уровне игнорируются (прямая совместимость).
`null`-поля при экспорте не пишутся.

## 3. Поля задачи

В файл попадают только поля, допустимые для создания и обновления задачи.

| Поле | Тип | Правила |
|------|-----|---------|
| `id` | GUID | исходный идентификатор; используется только для поиска конфликтов, не является привилегией |
| `name` | string | обязательное, непустое |
| `description` | string | |
| `enabled` | bool | при `hasPassword = true` импорт принудительно ставит `false` (раздел 8) |
| `programPath` | string | локальный абсолютный путь с прямыми слэшами |
| `arguments` | string | |
| `workingDirectory` | string | локальный абсолютный путь или пусто |
| `windowStyle` | `"Normal"` / `"Hidden"` / `"Minimized"` / `"Maximized"` | |
| `sessionMode` | `"Headless"` / `"ActiveUser"` | `ActiveUser` в v1 отклоняется службой |
| `runAsUser` | string? | только администратор |
| `runAsDomain` | string? | только администратор |
| `hasPassword` | bool | только информационный флаг |
| `onError` | `"SkipNext"` / `"Retry"` / `"Fail"` | |
| `retryCount` | int | 0…10 |
| `onOverlap` | `"WaitComplete"` / `"WaitNext"` / `"StartAnother"` | |
| `timeoutMinutes` | int? | 0…10080 |
| `killOnTimeout` | bool | |
| `logOutput` | bool | |
| `maxHistoryRecords` | int | 1…10000 |
| `timeWindows` | `TimeWindowDto[]` | не более 1000 на задачу |

Поля `owner`, `createdAt`, `modifiedAt`, `password`, `encryptedPassword`
и `runAsPasswordEncrypted` в файл не попадают (раздел 5).

## 4. Триггеры

Элемент `timeWindows[]` использует модель `TimeWindowDto` из `IPC.md`:
`id`, `type`, `kind`, `startDate`, `endDate`, `daysOfWeek`, `daysOfMonth`,
`specificDates`, `exactTimes`, `startTime`, `endTime`,
`repeatIntervalMinutes`, `repeatUntil`, `dayInterval`, `weekInterval`,
`monthInterval`.

- `id` триггера — информационное поле источника.
- Перед `CreateTask` и `UpdateTask` UI очищает `timeWindows[].id`
  (пустой GUID); служба генерирует новые идентификаторы.
  Это исключает конфликт первичного ключа при повторном импорте копии.
- `type` — устаревшее поле; актуальный тип задаёт `kind`.
- Валидация расписаний — по правилам `IPC.md`, раздел 5.
- Время — `HH:mm` в 24-часовом формате; даты — `yyyy-MM-dd`.

## 5. Секреты и служебные поля

В файл не попадают:

- `password` — пароль в открытом виде;
- `encryptedPassword` — зашифрованный пароль из БД;
- `runAsPasswordEncrypted` — зашифрованный пароль модели `TaskDto`;
- `owner` — сведения о владельце;
- `createdAt`, `modifiedAt` — служебные метки времени.

Если вручную добавленное поле из этого списка встретилось при чтении,
оно игнорируется, в отчёт добавляется предупреждение. Содержимое таких полей
никогда не передаётся в IPC и не пишется в логи.

`hasPassword` остаётся только для предупреждения при импорте.

## 6. Лимиты и локальная валидация

| Ограничение | Значение | Поведение при превышении |
|-------------|----------|--------------------------|
| Размер файла | 8 МиБ | отказ от импорта целиком |
| Задач в файле | 5000 | отказ от импорта целиком |
| Триггеров на задачу | 1000 | задача не проходит валидацию |
| Длина строки | 64 КиБ (65 536 символов) | задача не проходит валидацию |

До вызова IPC UI проверяет: обязательные поля, GUID, перечисления, диапазоны,
форматы `HH:mm` и `yyyy-MM-dd`, правила триггеров и лимиты.
Задача, не прошедшая локальную валидацию, получает результат `Failed`
с кодом `VALIDATION`; остальные задачи продолжают импортироваться.
Несуществующий путь программы или рабочего каталога — предупреждение,
а не ошибка.

Ошибки шапки (размер файла, число задач, `format`, `formatVersion`,
битый JSON) прерывают импорт до первого вызова IPC.

## 7. Режимы импорта

| Режим | Поведение |
|-------|-----------|
| `copy` (по умолчанию) | всегда `CreateTask` с новым GUID; имя сохраняется |
| `skip` | если `id` есть среди видимых задач — пропустить; иначе `CreateTask` с исходным `id` |
| `overwrite` | если `id` совпал со **своей** задачей — `UpdateTask`; иначе `CreateTask` с новым GUID |

- При отсутствии или пустом `id` конфликт не обнаруживается, задача создаётся.
- Режим `overwrite` не перезаписывает чужие задачи: служба проверяет владельца,
  а UI не видит чужие задачи у не-администратора.
- Каждая задача — отдельный вызов IPC; частичный успех допустим.
- Отмена прекращает обработку очереди; уже импортированные задачи сохраняются.
- После импорта UI обновляет дашборд.

## 8. Пароль и выключение задачи

Пароли не экспортируются и не импортируются из файла.

Если `hasPassword = true`, пароль в файле отсутствует, поэтому:

- задача создаётся или обновляется с `enabled = false`;
- в отчёт добавляется предупреждение
  «Задайте пароль и включите задачу».

Правило действует независимо от значения `enabled` в файле.
Если `hasPassword = false`, `enabled` переносится из файла без изменений.

Не-администратор импортирует задачи только себе; `runAsUser`, `runAsDomain`
и `sessionMode = "ActiveUser"` отклоняются службой по существующей политике.
Администратор также импортирует задачи себе.

## 9. Отчёт импорта

Отчёт формируется в UI и не является частью файла обмена:

- счётчики `imported`, `skipped`, `updated`, `failed`;
- результат по каждой задаче: исходный `id`, имя, итог, код ошибки
  (`VALIDATION`, `AUTH_DENIED`, `NOT_FOUND`, `CONFLICT`, `DB`, `INTERNAL`)
  и текст причины;
- общие предупреждения: `hasPassword`, лишние секретные поля, отсутствие пути.

Отчёт можно скопировать в буфер обмена и записать в локальный лог UI.
Пароли и содержимое файла в лог не попадают.

## 10. Аудит

- Экспорт — операция чтения; отдельная запись аудита не создаётся,
  UI пишет строку в локальный лог.
- Импорт использует существующие записи аудита службы `CreateTask` /
  `UpdateTask` — по одной на задачу.
- В аудит и логи не попадают пароли и полное содержимое файла.

## 11. C#-модели

Модели находятся в `./src/WinSheduler.Shared/Models/`:

- `TaskExchangeDocument` — шапка и `tasks[]`;
- `TaskExchangeTask` — задача обмена; намеренно не наследует `TaskDto`,
  чтобы секреты не попали в сериализацию;
- `TimeWindowDto` — переиспользуется из `IPC.md`;
- `TaskExchangeOptions` — режим и лимиты импорта;
- `TaskImportMode` — `Copy` / `Skip` / `Overwrite`;
- `TaskImportOutcome` — `Imported` / `Skipped` / `Updated` / `Failed`;
- `TaskImportItemResult` — результат одной задачи;
- `TaskImportReport` — счётчики, результаты и предупреждения;
- `TaskExchangeJson` — константы формата, лимиты и общие
  `JsonSerializerOptions`: camelCase, `JsonStringEnumConverter`,
  `WriteIndented`, игнорирование `null` при записи.

Маппинг:

- `TaskExchangeTask.FromTaskDto` копирует только разрешённые поля,
  включая `hasPassword`; секреты и владелец отбрасываются.
- `TaskExchangeTask.ToTaskDto` не заполняет `Password`,
  `RunAsPasswordEncrypted` и `OwnerSid`, а также очищает
  `timeWindows[].id` перед отправкой в IPC.
- `TaskExchangeJson.CreateDocument` заполняет `format`, `formatVersion`
  и `exportedAt` (UTC с `Z`).

## 12. Совместимость

- Новые необязательные поля можно добавлять в пределах `formatVersion = 1`;
  старые читатели их игнорируют.
- Удаление и переименование полей, изменение семантики — только в версии 2
  через ADR.
- Файл более новой версии не читается частично: отказ до вызова IPC.

## 13. Критерии приёмки

- Round-trip: экспорт → импорт в чистую БД → поля и триггеры совпадают.
- В файле нет `password`, `encryptedPassword`, `runAsPasswordEncrypted`,
  `owner`, `createdAt`, `modifiedAt`.
- `formatVersion = 2` даёт понятную ошибку; битый JSON и пустой `tasks`
  обрабатываются по разделу 2.
- Режимы `copy` / `skip` / `overwrite` работают по разделу 7.
- `hasPassword = true` без пароля → задача выключена и есть предупреждение.
- Повторный импорт копии не даёт конфликта идентификаторов триггеров.
- Лимиты из раздела 6 соблюдаются.
