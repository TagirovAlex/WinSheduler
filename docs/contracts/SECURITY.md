# Контракт безопасности

Статус: заморожен. Изменения — только через ADR.

## 1. Границы доверия

```
Пользователь (UI, asInvoker)
  │  named pipe //./pipe/WinSheduler
  ▼
Служба (session 0, LocalSystem)
  ├─ SQLite (ProgramData, ACL SYSTEM/Admins)
  ├─ Логи (ProgramData, ACL SYSTEM/Admins)
  └─ Дочерние процессы
       ├─ headless от имени клиента (не-админ)
       └─ SYSTEM / RunAsUser (только админ)
```

Ключевое правило: **членство в `WinSheduler Users` не даёт прав администратора и не позволяет запускать задачи от SYSTEM или от чужого имени.** Иначе группа была бы эквивалентна администратору.

## 2. Группа и матрица прав

Локальная группа `WinSheduler Users` создаётся установщиком. Она не входит в `Administrators` и не имеет Windows-привилегий. Её единственная роль — разрешить подключение к IPC.

| Операция | Оператор | Администратор |
|----------|----------|---------------|
| Подключение к IPC | да | да |
| Просмотр своих задач | да | да |
| Создание/изменение/удаление своих задач | да | да |
| Запуск своей задачи от своего имени | да | да |
| Просмотр/изменение чужих задач | нет | да |
| `RunAsUser`, `RunAsDomain`, `Password` | нет | да |
| Задача от SYSTEM | нет | да |
| `SessionMode=ActiveUser` | нет | да (резерв) |
| Аудит, настройки, управление службой | нет | да |

Не-админская задача запускается **токеном клиента**:

1. `ImpersonateNamedPipeClient`.
2. `OpenThreadToken` → `DuplicateTokenEx(TokenPrimary)`.
3. `CreateProcessAsUser` с этим токеном.
4. Процесс наследует права пользователя, а не службы.

Админская задача без `RunAsUser` запускается токеном службы (SYSTEM). Это явно показывается в UI бейджем «SYSTEM».

UAC: неэлевированный администратор имеет filtered token. `CheckTokenMembership(Administrators)` вернёт false, поэтому он обрабатывается как оператор. Для привилегированных действий UI перезапускается через `runas` (кнопка «Запустить от администратора»).

## 3. Named pipe

- Имя: `//./pipe/WinSheduler`.
- Режим: byte, `PIPE_REJECT_REMOTE_CLIENTS`.
- SID группы установщик пишет в `HKLM/SOFTWARE/WinSheduler`, значение `GroupSid`; служба читает его один раз при старте и кэширует. Fallback — `LookupAccountName`, затем доступ только `SYSTEM` + `Administrators`.
- SDDL (пример; точный SID группы подставляет установщик):
  - `SYSTEM` — полный доступ;
  - `Administrators` — полный доступ;
  - `WinSheduler Users` — `GRGW` (чтение/запись), без `FILE_CREATE_PIPE_INSTANCE`.
- Лимит инстансов: 64. При превышении — `ERROR_PIPE_BUSY`/отказ.
- Таймаут чтения кадра: 30 секунд. Медленный клиент отключается.
- Максимальный кадр: 1 МиБ; глубина JSON: 64; строка: 64 КиБ.
- Один запрос — один ответ; конвейеризация запрещена.
- При ошибке аутентификации — закрыть соединение, записать в аудит, не раскрывать детали.

## 4. Секреты

- Пароли принимаются службой только по защищённому каналу (ACL + impersonation) и сразу шифруются `CryptProtectData` с `CRYPTPROTECT_SYSTEM`.
- UI никогда не шифрует пароль и никогда не получает blob обратно. В DTO — только `hasPassword`.
- В памяти: `SecureZeroMemory`/`RtlSecureZeroMemory` после использования. Строки C# с паролем не создаются: используется `SecureString` или unmanaged buffer.
- В логах, аудите и ошибках пароль не появляется. Командная строка процесса логируется с редактированием секретов.
- Старые пароли, зашифрованные `CRYPTPROTECT_LOCAL_MACHINE`, считаются скомпрометированными и требуют ротации при миграции.

## 5. Валидация путей

Для `programPath`, `workingDirectory`, путей вывода:

- только локальный абсолютный путь (`d:/...` или `//server/...` запрещён);
- запрещены UNC (`//`), device paths (`//?/`, `//./`), `..`, альтернативные потоки (`:` после буквы диска), пустые сегменты;
- запрещены пути внутри `%TEMP%` пользователя, если задача создаётся не-админом;
- путь должен существовать на момент запуска; проверка — перед `CreateProcess`;
- рабочая папка — локальная, существует, не является корнем диска;
- путь вывода строится только из серверного GUID: `./logs/output/<taskId>/<historyId>.log`;
- клиентский `id` никогда не используется в путях.

Для установщика дополнительно: проверка ACL родителей (см. `./docs/contracts/INSTALL.md`).

## 6. Аудит

Пишутся:

- создание, изменение, удаление задачи;
- включение/выключение;
- `RunNow`;
- неудачная аутентификация/авторизация;
- изменение настроек;
- миграция БД и старт/остановка службы.

Поля: `ts`, `actor_sid`, `action`, `object_type`, `object_id`, `result`, `details`. `details` не содержит секретов и путей, раскрывающих чужие данные.

Доступ к аудиту — только администратор.

## 7. Логи

- Каталог логов — `DATADIR/logs`, ACL `SYSTEM`/`Administrators`.
- Формат: `время | уровень | компонент | сообщение`.
- Обязательное редактирование: пароли, токены, содержимое `RunAsPassword`.
- Запрещены переводы строк из пользовательских данных (защита от log injection): символы возврата каретки и перевода строки заменяются на пробел.
- Ротация по размеру и по дням; retention настраивается.

## 8. Установка и служба

- `INSTALLDIR` — по умолчанию `%ProgramFiles%/WinSheduler`, ACL `SYSTEM`/`Administrators` full, `Users` read+execute.
- `DATADIR` — по умолчанию `%ProgramData%/WinSheduler`, ACL `SYSTEM`/`Administrators` full, `Users` без доступа.
- Кастомный `INSTALLDIR` запрещён, если родительский каталог доступен не-администраторам на запись/удаление дочерних объектов. Обход — только `ALLOWUNSAFEPATH=1` для лаборатории.
- Служба: `LocalSystem`, auto delayed, recovery 5/30/60 с, reset 1 день, `SERVICE_ACCEPT_PRESHUTDOWN`.
- Бинарники и данные не размещаются в профиле пользователя и в каталогах, доступных на запись обычным пользователям.

## 9. Модель угроз

| Угроза | Контрмера |
|--------|-----------|
| Локальный пользователь подменяет exe службы | Program Files + ACL + проверка родителей |
| Локальный пользователь читает пароли | DPAPI SYSTEM, ACL БД, пароль не отдаётся в IPC |
| Локальный пользователь создаёт задачу от SYSTEM | матрица прав, токен клиента |
| Path traversal через `taskId` | GUID-валидация, серверные пути |
| UNC-путь → утечка NTLM | запрет UNC/device paths |
| Медленный/вредоносный клиент исчерпывает потоки | лимит инстансов, таймаут, лимит кадра |
| Глубокий JSON → переполнение стека | лимит глубины 64 |
| Подмена БД | ACL, `quick_check`, подпись установщика (когда появится) |
| Компрометация обновления | SHA256-манифест, будущая подпись, отсутствие сетевых зависимостей |
