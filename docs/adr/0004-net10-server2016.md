# ADR 0004 — .NET 10 и минимальная ОС Windows Server 2016

Статус: принято.
Дата: 2026-11-06.

## Контекст

- .NET 8 LTS заканчивает поддержку **10.11.2026**; нужен поддерживаемый рантайм.
- Требуется работа на **Windows Server 2016** (build 14393) и совместимость
  с Windows 10 1809+/Server 2019+.
- Текущий порог установщика `build >= 17763` — продуктовое решение, не
  техническое ограничение: служба собрана `/MT`, PE subsystem version `6.00`,
  импортируются только API уровня Vista/Win7.
- .NET 10 LTS поддерживается до **14.11.2028** и официально поддерживает
  Windows Server 2016 (включая Desktop Runtime).

## Решения

1. UI — `net10.0-windows`, Shared и тесты — `net10.0`; SDK фиксируется
   в `./global.json` (10.0.4xx).
2. Минимальная ОС — Windows 10 1607 / Server 2016 (build 14393).
   Установщик проверяет `build >= 14393`.
3. UI требует Server 2016 с **Desktop Experience**; служба поддерживается
   и на Server Core.
4. Управляемые проекты собираются через `dotnet build` (SDK 10.0.4xx);
   C++ — через MSBuild из VS 2022. VS 2026 для CLI-сборки не обязателен.
5. `_WIN32_WINNT=0x0601` и `WINVER=0x0601` задаются глобально в vcxproj,
   чтобы случайно не использовать API новее целевой ОС.
6. Манифест UI (`PerMonitorV2`, `activeCodePage`) не меняется: на 1607
   неизвестные значения игнорируются, WPF откатывается к system DPI.

## Последствия

- VS 2022 17.14 не поддерживает targeting `net10.0`; сборка управляемых
  проектов идёт через `dotnet build`, а не через MSBuild решения.
- Server 2016 находится на расширенной поддержке до 12.01.2027 — это
  ограничение ОС, а не приложения.
- Нужен smoke на реальной ВМ Server 2016 (Desktop Experience) и проверка
  службы на Server Core.
- .NET Runtime на целевой машине не требуется: UI публикуется self-contained.

## Альтернативы

- Остаться на .NET 8 — отклонено: EOL 10.11.2026.
- .NET 9 — отклонено: STS, EOL 10.11.2026.
- Оставить минимум 1809 — отклонено: не покрывает парк Server 2016.
- Собирать всё через VS 2022 — отклонено: targeting net10 официально
  не поддерживается; CLI-сборка надёжнее.
