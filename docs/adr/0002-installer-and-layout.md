# ADR 0002 — Установщик и раскладка

Статус: принято.
Дата: 2026-11-01.

## Контекст

Текущая установка (`./deploy.bat`) регистрирует службу из пользовательского каталога и не настраивает ACL. `./publish.ps1` удаляет `./published` вместе с базой задач. Нужен воспроизводимый установщик с поддержкой кастомного пути.

## Решения

1. WiX Toolset, MSI, per-machine.
2. UI публикуется self-contained (`win-x64`), prerequisite .NET не требуется.
3. `INSTALLDIR` по умолчанию `%ProgramFiles%/WinSheduler`, но может быть переопределён.
4. `DATADIR` по умолчанию `%ProgramData%/WinSheduler`, может быть переопределён.
5. Кастомный `INSTALLDIR` валидируется: локальный фиксированный диск, не корень, не профиль, ACL родителей без записи для не-админов.
6. ACL выставляются явно: `SYSTEM`/`Administrators` full, `Users` read+execute для программы; данные — без доступа для `Users`.
7. Служба: `LocalSystem`, auto delayed, recovery 5/30/60 с, `SERVICE_ACCEPT_PRESHUTDOWN`.
8. Локальная группа `WinSheduler Users` создаётся установщиком; SID подставляется в SDDL pipe.
9. Данные не входят в компоненты MSI; при удалении сохраняются по умолчанию.
10. Подпись — заглушка до появления сертификата; SHA256-манифест обязателен.
11. CI нет: сборка и проверка локальные.

## Последствия

- `./deploy.bat` выводится из production-процесса.
- `./publish.ps1` перестаёт удалять данные и публикует в `./artifacts/`.
- Появляются `./installer/**` и `./scripts/installer/**`.
- Нужны тесты на чистых ВМ и проверка ACL.
- Размер MSI — 60–80 МБ из-за self-contained UI; это принято.

## Альтернативы

- Inno Setup — отклонено: нет MSI/GPO-интеграции.
- MSIX — отклонено: не поддерживает службы.
- Framework-dependent UI + Burn — отклонено: лишняя зависимость и сложность; self-contained надёжнее для offline.
