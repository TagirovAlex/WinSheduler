# ADR 0003 — Планировщик, headless-режим и IPC v1

Статус: принято.
Дата: 2026-11-01.

## Контекст

Текущий планировщик не соблюдает расписание: `last_run_minute_` хранится на задачу, интервальные задачи срабатывают каждую секунду, `SpecificDates` и диапазоны дат игнорируются, интервалы N дней/недель/месяцев не сохраняются. IPC не имеет версии, кадрирования и лимитов.

## Решения

### Планировщик

1. Явная модель `TriggerKind`: `Once`, `Daily`, `Weekly`, `Monthly`, `Interval`.
2. Состояние срабатываний — `trigger_state(task_id, window_id, slot, last_fired_at)`.
3. Слот — локальное `yyyy-MM-ddTHH:mm`; повторный запуск в том же слоте запрещён.
4. Даты, `SpecificDates`, `DayInterval`/`WeekInterval`/`MonthInterval`, `RepeatUntil` реализуются полностью.
5. Интервал срабатывает ровно раз в N минут; очередь ожидающих запусков коалесится.
6. Время событий — UTC; расписание — локальное настенное; политика DST описана в контракте.
7. При старте осиротевшие `Running` помечаются `Aborted`.

### Headless

8. v1 поддерживает только headless-задачи.
9. `session_mode` (`Headless`/`ActiveUser`) резервируется; `ActiveUser` в v1 отклоняется.
10. `WindowStyle` не перемещает процесс в сессию пользователя; в UI это поясняется.

### IPC

11. Кадрирование: 4 байта длины + UTF-8 JSON.
12. Конверт с `v`, `id`, `action`, `payload`; ответ с `ok`, `error`, `payload`.
13. Лимиты: 1 МиБ, глубина 64, строка 64 КиБ.
14. `GetDashboard` заменяет 2N+1 вызовов.
15. Legacy-конверт `{Action, Payload}` поддерживается временно.

## Последствия

- Появляются `trigger_engine.*`, `trigger_state`, `session_mode`.
- Требуется миграция БД v1→v2.
- UI и служба обновляются одновременно (протокол несовместим с legacy по кадрированию).
- Нужны тесты с fake clock.
- Интерактивный режим потребует отдельного ADR: `WTSQueryUserToken`, `winsta0/default`, fallback при отсутствии сессии.
